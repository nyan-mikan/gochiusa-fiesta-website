# 昵称、祝福语限额与删除

账号设置支持保存昵称（最多 40 字符，去除首尾空白并规范 Unicode，不允许换行或控制字符），留空时显示邮箱前缀。昵称显示在侧栏账号卡片，也是新祝福语署名的默认值，不改写已经提交的署名或账号邮箱。昵称只允许当前账号修改，审计不保存昵称正文。

私钥文件选择或拖入后，文件选择区隐藏。浏览器使用独立的 `identify-private-key` 挑战证明持有私钥，服务器返回此密钥账号的当前昵称或邮箱前缀，再询问「是否登录该账号」。识别步骤不创建登录会话、不返回邮箱地址；用户确认后使用新的 `login-private-key` 挑战登录，取消则清除浏览器中的密钥并重新显示文件选择区。两种挑战不可互换、均只使用一次；旧私钥文件无需重新下载，账号名始终来自签名验证后的数据库查询。

每个账号在同一活动仅允许一则祝福语，包括管理员。重复建立草稿返回既有草稿，提交后不允许再建或提交第二则。不同活动各自计算限额；已提交时页面隐藏填写表单。D1 插入/提交触发器和原子事务处理并发，不能绕过前端限制。迁移保留此前可能已有的重复历史，不删除或改写已有祝福语；如果已有提交，其他遗留草稿不能再提交。

「我的投稿」列表和草稿详情提供删除按钮，并先询问确认。仅本人可删除从未提交过的 draft；待审核、通过、驳回及包含已提交历史的作品均不能删除，管理员不能代删。删除校验当前版本，和保存/提交发生并发时最多一个成功。删除采用隐藏记录的方式，保留审计和版本关联；草稿不再出现在任何列表、详情或附件入口，也不能继续上传、保存或提交。解除文件引用后，现有定时任务分批清理 R2 文件和未完成上传，无新服务。

主持稿点击「批量删除台词」后可逐条勾选、选择本段、全选或清空，每批最多 100 条，包含台词、注释和小标题。选中内容的历史快照超过 1,000,000 字节时要求减少选择、分批删除，避免超过 D1 行限制。未保存内容先完成保存，确认框显示条目数量。选中行和所在段落的版本一起验证，发生冲突时整批不删除；定稿状态拒绝删除，跨活动行也拒绝。使用现有每活动 DO 和单个 D1 batch 更新各行及相关段落版本，只产生一个变更序号；历史和多人片段保留，重试同一操作不会重复删除。

## 迁移和检查

追加 `0014_account_and_deletion.sql`：users.nickname、submissions.deleted_at、签名挑战用途，以及祝福语数量/草稿删除/晚到上传约束。应用迁移后再部署新 Worker；不更改正式投稿、节目、主持稿或祝福语内容。

运行类型、构建、实际本地集成、脚本合并与文件拖入检查；`scripts/account-features-checks.mjs` 集成于 `npm run test:integration`。`node scripts/private-key-browser-check.mjs` 也调用 `account-features-browser-checks.mjs` 检查昵称、私钥确认/取消、祝福语限额、草稿列表/详情删除和手机批量操作，全程使用本地测试邮箱与临时文件。
