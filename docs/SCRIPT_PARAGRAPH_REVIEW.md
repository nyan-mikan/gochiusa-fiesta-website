# 主持稿段落审阅

单句和段落分别缓存、分别给建议。离开台词、角色或舞台提示字段时，单句先保存并登记审核；段落等待短暂稳定后登记整段。已有段落结果的内容或结构发生变化时自动重新登记，也可点击段落中的“检查段落”。等待后台反馈期间可以继续写稿、保存和切换页面，审核不会自动改稿或阻止定稿。

在“段落设置”中填写可选的“场景与地点”，例如“Rabbit House 室内，开场后仍在店内”。此字段与段落其他设置一样使用版本检查保存。没有填写时，可从明确的舞台提示、注释或台词获取地点依据；依据不足时不默认在 Rabbit House，也不把空地点本身当错误。

检查段落内的时间、事实、因果与行动冲突，必要铺垫和可解析指代是否缺失，以及发言是否与明确场景/地点相矛盾。小标题、注释、舞台提示和关联节目背景参与解释；换场、回忆、时间推进、引用或玩笑可以解释表面的差异。只判断有具体依据的问题，不凭空补故事，也不因未提供整场前文就认定缺失。CB 的友情、搭档及姐妹亲近继续允许。

反馈关联具体台词原文。一个逻辑矛盾可在两句或多句下方同时显示黄色三角警告，并进入系统消息，每处标注都可定位对应句子。忽略同一问题会隐藏它的全部关联标注，按用户永久保存；其他用户仍看到自己的提示。刷新读取同一标识结果，不重新请求，完成且没有问题也缓存。

每个标识冻结段落标题、场景、节目背景、角色预设、台词版本和顺序。修改任一句、角色、舞台提示、场景、节目背景或重排、增删、拆分合并都会改变上下文；旧结果即使迟到也不显示在新稿上，新标识不继承旧忽略。无关段落编辑不使该段落重新审核。单句“已审阅”仍表示该句审核完成，段落另显示“段落已审阅”；两者都不表示所有警告已修复。

后端将临时句编号交给服务，并把有效编号映射回已冻结的台词。不存在的编号、非原文引用、重复目标或配置泄露内容不能成为页面标注。接口保留主持稿模块权限、CSRF 和保存版本校验，前端仅取得结果、相关句标识和普通上下文匹配键；不会取得模型配置、供应商响应或预设快照。

沿用现有 OpenAI 兼容配置、ScriptRoom alarm、定时任务及 D1；无需新 Key 或 Cloudflare 服务，未配置时不派发。单句/段落按登记时间交接，慢段落之后新登记的单句继续处理。每个标识最多派发一次，失败或响应丢失不自动重试；修改得到新标识。没有每日上限，保留每用户每分钟新登记 30 个单句和 30 个段落的并发保护。

单次段落最多 500 条、正文和舞台提示合计 100,000 字，冻结请求不超过 1,000,000 字节；超出时提示拆分段落，不静默截断。最多 20 个问题，每个问题最多关联 20 句。模型理解仍可能漏判或误判，可忽略并自行修改；本地模拟测试验证传递、定位和持久化，不代表实际供应商的全部语义判断质量。

部署前先应用增量迁移 `0018_paragraph_reviews.sql`。它追加可选场景字段及审核、输入、问题、目标、忽略表与不可变约束；历史台词、单句反馈及忽略记录保持不变。配置说明见 [SCRIPT_LANGUAGE_REVIEW.md](SCRIPT_LANGUAGE_REVIEW.md)。
