# 祝福语投稿

2026-10-03。入口 `/wishes`，管理员管理页 `/admin/wishes`。沿用真实邮箱登录及现有 admin/submitter 权限。

普通用户可填写署名与最多 2000 字文本。管理员可提交文本、纯语音或文本加语音；每份音频不超过 20 MiB，支持 MP3、WAV、M4A、OGG、FLAC、WebM。服务端检查格式头与真实字节数，普通账号即使直接调用上传 API 也返回 403。媒体的编码兼容性仍取决于浏览器，不进行自动转码。

祝福语与作品投稿使用独立开关：活动设置中的“开放祝福语投稿”。迁移默认开启，活动必须可见；管理员可在关闭时录入收集到的祝福语。创建、提交均通过操作 ID 幂等；发布时检查当前会话、账号权限和版本。提交后内容冻结，数据库触发器阻止修改及对已提交内容追加/替换音频。每人最多保留 10 份未提交草稿，可从“我的祝福语”继续。

数据库新增两张 3NF 表：wishes 的身份决定活动、投稿者、署名、文本和状态；wish_audio 以 wish_id 唯一关联音频，记录对象键、原始名称、实际类型、大小和摘要。音频字节只放入现有 UPLOADS 私有 R2 桶的 wishes/ 前缀，不放入 D1。作者身份通过 FK 推导，不重复保存邮箱。两表加上已有表总计 38 张业务/辅助表。

管理员可按署名/正文搜索、分页查看、播放及下载语音。播放支持 HTTP Range；本人也可播放自己的语音，其他普通账号不能读取。API 与 ZIP 不包含登录邮箱。音频不公开为 R2 公共对象地址，始终通过同源权限检查。

批量导出可勾选本页条目；未勾选时导出当前活动全部已提交内容（包括搜索结果之外的内容）。文本 ZIP 每条一个带署名、投稿时间、正文的 UTF-8 TXT，最多 1000 条。音频 ZIP 保留原文件字节，单次最多 100 份且合计不超过 1 GB；超出时要求勾选后分批导出。文件名移除路径和控制字符、添加稳定编号及短 ID。服务端按需流式读取 R2 和生成 ZIP，浏览器直接保存下载，不将整包读入 Worker 或网页内存；取消下载会关闭流。

未提交输入在本机 localStorage 按账号和活动隔离备份。音频选择不进入本地备份；尚未成功上传的文件在刷新后需要重新选择。失败保留文本及草稿 ID，可重试；服务器只展示已提交内容给管理员。

## 验证

此前 224 项本地真实 HTTP 检查通过。2026-10-04 接入 R2 后，60 项既有 staging 检查再次通过；新增 scripts/r2-staging-check.mjs 的 38 项真实云端检查包含音频上传、20 MiB + 1 拒绝、格式头、幂等和提交冻结、完整 WAV 字节下载、Range、原始音频 ZIP 解压字节一致性及普通账号越权拒绝。没有使用正式用户会话或向真实邮箱发送测试邮件；测试完成后撤销会话并停用账号、关闭活动、删除 R2 测试对象。

实际浏览器使用独立本地测试活动：管理员选择程序生成的 1 秒 WAV（测试音，不是真人录音），提交文本加语音；管理页播放成功，duration=1、readyState=4、无媒体错误。文本和音频 ZIP 通过网页按钮下载到本地，解压分别核对正文和完整 WAV 字节。普通用户真实 OTP 登录后无文件输入控件，文本提交刷新保留，1280px DOM 视口无页面水平溢出。截图为本地测试资料：screenshots/wishes-management-local.png、screenshots/wishes-text-submission-local.png。不代表新增手机/完整媒体编解码矩阵验收。
