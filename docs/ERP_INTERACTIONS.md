# 字段帮助、消息与管理应用

仅有真实候选列表的输入选择字段通过共享 FieldLabel 提供 Help 和 F1/F4 快捷键。按维护者最终确认的交互，双矩形 Help 直接展开输入框下方带编号与名称表头的候选表，不打开居中的说明或选择窗口。直接点击或聚焦文本框只定位光标；输入时才显示匹配候选，清空输入后关闭。点击 Help 展示全部可选资料；点击候选回填并关闭，返回文本框的焦点不再次打开列表。普通下拉菜单只保留原箭头，不显示双矩形图标，F1/F4 可展开候选。自由文本、UID、链接、文件、长文本、复选框及没有预设候选的数值字段不显示 Help，也不打开说明弹层；原有填写提示保留。日期时间字段使用原生日期选择入口。

年份按原限制提供 2000–2200 候选并保留直接数字输入；时区使用浏览器支持的真实时区列表、UTC 与当前有效时区。已有 select/datalist 支持候选回填，普通下拉框仍只显示原生箭头。当前值高亮，禁用选项和只读字段不能修改；回填时重新检查原字段状态和候选键，避免资料变动后选错项。候选表根据视口空间调整位置，高度受限并可滚动，Escape 或点击外部关闭。节目类型、B站分区、制作职务的 Help 使用现有输入匹配表，输入按编号/名称匹配，保留方向键、Enter/Escape 与组合输入处理；只选择已有选项 ID，未匹配文本不能通过投稿检查。

输入确认参照 SAP 官方 OpenUI5 `InputBase.change`：值改变后，失焦或按 Enter 都能触发确认，Enter 不是每个字段的必需步骤。普通字段继续按自己的保存规则处理，不因未按 Enter 提示警告。候选输入支持完整名称与显示编号的唯一精确匹配，输入有效完整值、Tab 或切换字段即可接受；部分文字只筛选，不在失焦时强行选择或报错。Enter 用于确认当前高亮项、唯一匹配或唯一候选，多个匹配时保留候选表供选择，中文输入法的确认键不触发业务提交。候选确认的 Enter 不会顺便提交整份表单。

手机不依赖 Enter：点候选直接回填，完整有效值在切换字段、点击保存或提交时确认。保存草稿只检查已输入的候选内容，不强制草稿填写所有必填项；未匹配的候选文本在明确保存或提交时拒绝，防止仍显示新文字却保存上一次 ID。自动保存继续保留已确认的数据，不把未匹配文本创建为字典记录。普通下拉、原生日期选择器以及文本/台词换行保持各自操作。官方依据：[@openui5/sap.m](https://www.npmjs.com/package/@openui5/sap.m) 1.153.0 的 `src/sap/m/InputBase.js` 中 `change`、`onsapenter`、`onsapfocusleave`，及 `Input.js` 中候选选择的 Enter 处理。

页面底部使用固定状态栏，桌面宽度仅覆盖右侧内容区，菜单栏不被遮挡；消息列表也在内容区左下角展开。手机导航位于顶部，底栏按可用视口宽度排列。底栏左侧只显示紧凑的消息数量按钮。错误用红色圆形叉号，警告用黄色三角叹号，成功与普通状态用蓝色图标；不显示 E/W/S 字母，不使用绿色。依靠形状、数量与可访问名称辨识，不只依靠颜色。点击按钮在上方展开消息列表，按当前页面分组，有错误或警告时显示中文数量，以及消息正文与相关字段；点击消息可定位并聚焦字段。列表不遮暗页面，点击外部关闭，Escape 或关闭按钮返回消息按钮。没有消息时按钮显示 0，展开说明“当前没有错误或警告”及“提交时会检查必填项”，不将尚未检查的空表单视为验证通过。消息不写入 localStorage、不随导航保留；原有字段旁提示继续保留。

状态栏右侧通过共享 PageActions 排列页面操作，保存操作优先；主持稿“立即保存”为最右侧蓝色主按钮，“检查并定稿/解锁主持稿”为左侧次要按钮。涵盖操作：保存活动、分区保存与删除、节目编排保存与锁定、主持稿保存/定稿/导出/批量删除、投稿草稿保存/删除/提交、祝福语提交/批量下载、账号昵称与私钥操作、角色批量添加/列表创建、管理员任命及审核决定。搜索、分页、逐条编辑和弹窗确认仍保留在关联内容旁。外部提交按钮显式关联原表单，继续执行原生必填校验和页面提交检查；保留权限、忙碌状态、确认及版本冲突处理。活动设置初始化及节目编排切换加载期间禁用编辑/保存/锁定，避免操作旧活动快照。窄屏操作自动换行，页面按底栏实际高度预留空间，底栏设置高度上限，操作区可滚动。

管理入口 `/admin/apps` 提供投稿审核、节目编排、主持稿、角色管理、分区与职务、活动设置、祝福语管理；超级管理员还有“管理员与权限”。B站分区与制作职务从活动设置拆到 `/admin/dictionary`。角色继续使用独立角色管理页及版本检查；业务表单引用这些模块维护的 ID，不凭输入文字创建陌生职务或角色。

超级管理员在“管理员与权限”中分配七个管理模块。新任命管理员默认无模块权限；迁移为已有启用管理员保留原有七个模块。账号基础角色、超级管理员能力和模块授权分别保存，不互相冒充。普通管理员不能自行分配权限或任免管理员，超级管理员受保护。普通投稿、个人祝福语和账号设置不因缺少管理模块而禁用；管理员音频功能需要祝福语模块。

前端菜单和应用卡片只显示已授权模块，后端对 API、静态页面入口、协作变更和 WebSocket 重新核对权限。审核、字典、活动、脚本、节目、角色和祝福语音频写入在事务中复核会话/权限；权限变更使用账号版本、原子批次、操作 ID 和审计，并撤销旧会话。角色变为投稿者时移除模块授权。仅节目权限的读取不暴露台词正文，协作变更按模块筛选；本人以外的投稿、附件和祝福语读取也核对相应管理模块。

分区维护同时带 `expectedVersion` 和唯一 `operation_id`。多人从同一版本保存时只有一人成功，其他请求返回 409，整批不部分覆盖；恢复本机草稿仍使用原版本，不把最新版本号套到旧资料上。页面保留未保存内容，用户明确放弃后才重新读取。活动设置恢复草稿也保留原活动版本号。字典保存建立新的不可变职务定义、停用旧选项，原投稿引用保留；同名分区和重复职务标签拒绝，重试同一操作不重复建版本。界面仅显示分区名称，不显示版本号或「未启用」，版本号仍用于后台冲突检查。管理员保存即发布当前分区与职务，不提供停用保存状态；保存前需核对资料并填写 HTTPS 证据链接。删除使用模块权限、原会话、expectedVersion 和 operation_id 在原子事务中复核，整批移出管理及新投稿候选；旧编辑不能重新启用已删除记录。同名新建可沿用删除记录的 ID，但必须创建新的职务定义，不恢复旧选项。已提交投稿、外键与职务定义保留，历史详情从关联记录返回分区名，不依赖当前可选分区。保存与删除同时发生时只有一方成功；请求重试不重复写入或删除。原未启用条目也不再列入管理候选，可按新建分区重新维护。

追加迁移 `0015_modules_and_dictionary.sql`，只增加分区版本和 3NF 模块授权关系及约束。迁移不修改投稿、祝福语、角色或主持稿正文，不创建云端服务。

验证使用实际本地 D1/R2/DO 和 loopback 邮箱。`scripts/erp-checks.mjs` 接入 `npm run test:integration`，`scripts/erp-browser-checks.mjs` 接入 `node scripts/private-key-browser-check.mjs`。反复登录的本地测试通过识别新生成的分钟限流记录来模拟该测试账号冷却到期，不读取认证秘密、不降低生产限流，也不发送真实邮件。详细结果见 [VALIDATION.md](VALIDATION.md)。
