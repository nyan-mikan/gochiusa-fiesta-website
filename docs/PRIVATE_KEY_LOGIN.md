# 私钥登录

登录后展开侧栏底部账号菜单，进入「账号设置」。点击验证邮箱，输入发往当前账号邮箱的六位验证码，再生成私钥。首次生成与每次更换都必须重新验证邮箱。验证码有效期十分钟，最多五次错误尝试；发送间隔至少六十秒，每账号每小时最多六次请求。

浏览器使用 Web Crypto 生成 ECDSA P-256 密钥对。完成验证码和持有私钥的签名验证后，服务端保存 SPKI 公钥、SHA-256 公钥编码指纹、账号关联与生成时间。私钥以 PKCS#8 编码保存在下载的 JSON 文件中，只在当前页面内存中等待一次下载；没有私钥获取接口，不写入浏览器持久存储，私钥不会发送到服务器。下载后立即移除页面中的私钥副本。离开或刷新页面前会提示尚未下载的私钥。浏览器只能发起文件下载，用户须自行确认文件成功保存。

请妥善保管文件。私钥文件没有密码加密，任何获得文件的人都能登录账号。不要上传、分享或提交到 Git。仓库忽略 `gochiusa-private-key-*.json`。

登录页面可选择「私钥登录」，选择或拖入本站下载的 JSON 文件（最大 4 KiB）。文件仅在本机读取，导入后的密钥不可再次导出。登录只提交签名。签名涵盖用途、本站 origin、挑战 ID、密钥 ID 和随机 nonce；登录挑战有效期两分钟、最多五次错误、绑定请求 IP，成功后原子消费，不能重复使用。邮箱验证码登录始终保留。登录会话沿用七天、HttpOnly、SameSite=Lax 和线上 Secure cookie。

丢失私钥后，使用邮箱登录并重新验证邮箱，生成新私钥。数据库同时撤销旧公钥及其他通过旧私钥创建的登录会话。当前进行邮箱验证的会话会保留并解除旧密钥绑定；已有邮箱验证会话也保留。新密钥的领取验证码绑定账号、会话和生成挑战，不能跨账号、跨会话或拿登录验证码替代。每账号只能有一个有效公钥；更换、消费验证码和撤销会话通过同一 D1 batch 完成，旧公钥保留用于审计。禁用账号不能通过私钥登录。

## 数据库与发布

新增 `0013_private_key_login.sql`：`account_login_keys`、`key_email_challenges`、`login_key_challenges`、`key_sessions`。既有 users 和 sessions 结构保留，没有更改投稿、节目、R2 或 DO 数据。上线前先应用追加迁移，再部署 Worker；旧 Worker 兼容这些新增表，回滚代码不会删除密钥记录。无需新增凭据、邮件供应商或服务；领取验证码使用当前邮件适配器，本地使用 loopback 邮箱。

## 验证

运行 `npm run typecheck`、`npm run test:integration`、`node scripts/file-dropzone-check.cjs`。集成测试使用实际本地 D1、Worker 和 loopback 邮箱，覆盖生成、更换、邮箱找回、账号/会话绑定、签名、挑战重放与并发消费、过期、五次错误上限、IP、禁用账号和旧会话失效。为了避免等待发送间隔，测试只调整合成账号的本地时间/限流记录，不涉及远程数据。

有 Chromium 的 Linux 环境可额外运行 `node scripts/private-key-browser-check.mjs`（需要空闲的 8787、8025、9224 端口）。浏览器检查真实邮箱登录、账号菜单、实际一次性下载、未下载离页提醒、刷新后不可重下、390px 布局、文件选择/拖入和格式/大小拒绝，并核对 API 请求中没有私钥。测试临时下载文件与浏览器配置在结束后删除。

正式发布后可运行 `node scripts/smoke.mjs https://usagi.mikanyan.com` 和 `node scripts/private-key-production-check.mjs`。后者比较本地 dist 与线上私钥相关资源，并检查匿名保护、无效字段和 CSRF 拒绝，不创建生产测试账号、密钥或发送邮件。
